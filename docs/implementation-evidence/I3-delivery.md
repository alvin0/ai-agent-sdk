# I3 progress — Canonical delivery records, acknowledgments and staging

Date: **2026-09-05** (Asia/Ho_Chi_Minh).

Status: **Internal composition implementation; I3 is not complete.**

## Implemented

- A canonical `RunTerminalRecord` is projected from the real `RunLedger`. It
  retains reported and estimated usage separately, every model call and physical
  attempt, coverage, operation counts and bounded support-safe errors. It does
  not contain its own delivery result.
- Delivery batches carry separate event and run-record arrays and no batch-level
  usage scalar. Resource identity is generated by core; caller metadata is
  bounded, JSON-safe and cannot replace SDK/runtime identity or include known
  credential, path or content fields.
- Event and run acknowledgments use separate namespaces. Validation is atomic,
  rejects sparse/duplicate/foreign IDs and never reads accessors as data.
  Partial acknowledgments accumulate across retries of the exact same frozen
  batch and run-record objects. Late acknowledgments after timeout, cancellation
  or close cannot change acceptance.
- Privacy processing, canonical resource stamping and local staging now share one
  prepared event object. Each optional `stage()` hook is invoked synchronously
  after the queue owner admits that safe item. Synchronous failure, rejected or
  malformed promises and the health callback itself are contained; the next
  exporter still receives the item. Staging is explicitly not a durability
  receipt. Its final queue admission/checkpoint connection remains open.
- Delivery attempts now classify calls made before or during `RuntimeResources`
  shutdown as closed, do not leak a resource-owner exception, and commit no late
  acknowledgment.
- A batch checkpoint fans the exact same batch out under one absolute deadline.
  Every required exporter must complete; a best-effort failure remains visible
  but cannot block the required barrier. The reached boundary is the weakest
  selected boundary guaranteed by all required exporters, never the strongest
  isolated result. Completed attempts are not resent, incomplete attempts retain
  partial acceptance, and concurrent callers join the first checkpoint task.
- The bounded queue admission store uses the frozen 10,000-item/16 MiB defaults
  and separate 256-item/512 KiB batch defaults. It measures the exact one-item
  wire envelope before acceptance, privacy-processes once, stages only after
  admission, evicts the oldest verbose item before the oldest normal item, and
  never evicts critical evidence. Count and retained-byte limits are independent;
  all rejection and eviction counters saturate instead of wrapping. Event IDs
  and run IDs remain separate namespaces, and run selection includes only
  critical rows through the requested sequence plus its atomic terminal record.
- The scheduler converts a call-time queue snapshot into exact count/byte-bounded
  batches without repeated `Array.shift()`. Batches under required retry are
  protected from eviction and retain their IDs; best-effort terminal failures
  are released without changing the required checkpoint result. Flush calls are
  serialized while retaining their own target snapshots, partial acceptance is
  applied per event/run namespace, and expired/aborted/closed work neither
  allocates a new batch nor commits a late acknowledgment.
- The internal `RuntimeObservationPort` now composes synchronous privacy-safe
  capture, bounded diagnostics, local staging, serialized background flush and
  reliable/audit event checkpoints. An atomic terminal record has a separate
  `checkpointTerminal()` handoff, so the record never gains or depends on its
  own delivery result. Operational mode returns no durability claim; unavailable
  reliable/audit checkpoints reject. Duplicate capture/checkpoint calls do not
  duplicate staging or diagnostics, and the staging-failure support view is
  itself bounded to 64 safe records.
- A separate final-report projection combines the immutable terminal record with
  the completed terminal checkpoint. It preserves canonical usage/model-call/
  tool-source identities, counts the terminal record exactly once, chooses the
  weakest jointly reached boundary, saturates counters, and creates a fixed safe
  failure when delivery is unavailable. The ledger's internal
  `LegacyRunReport` is projected into the public canonical `RunReport extends
  RunTerminalRecord` schema; both low-level and runtime-owned agent handles now
  expose that single canonical report type, and manual compaction exposes the
  same type without a union. Mode, required boundary, run identity and
  accepted/durable/boundary consistency are revalidated before the final claim.
- The P0-09 diagnostic ring has independent count and serialized-byte limits,
  the approved provisional defaults of 256 events and 1 MiB, exact cumulative
  event/byte eviction counters, FIFO identity, immutable detached snapshots and
  cursor compaction. An event too large for an empty ring is rejected rather
  than falsely counted as a previously admitted eviction. This support view does
  not own or remove canonical ledger/exporter data.
- Automatic pressure/overflow compaction now binds its maintenance model call to
  the active run ledger. Runtime-owned manual compaction creates one canonical
  ledger, records its compaction operation and physical model call, checkpoints
  the terminal record, and returns the resulting report on a successful
  `CompactionResult`. Strict missing usage and aborts reject with the same frozen
  report; low-level `ContextCompactor` behavior remains compatible.
- Runtime observability now accepts and pre-captures processors, redactors and a
  synchronous span backend before resource allocation. Processor output is
  privacy-processed again before queue admission, invalid envelope mutation and
  callback failures are contained in health, and an invalid span backend falls
  back to core correlation. The observation shutdown timeout only shortens the
  shared runtime close deadline.
- Declaration migration removed the temporary legacy/canonical report union.
  Strict workspace typechecking, the core and compatibility-agent builds, and
  446 focused composition/accounting/compaction tests pass. Emitted declarations
  contain one public `RunReport` owner and `CompactionResult.report?: RunReport`.
  The aggregate contract gate currently stops at the historical I2 declaration-
  closure inventory because I3's newly emitted declaration chunks differ from
  that frozen phase snapshot; this is retained as an unresolved migration-gate
  issue rather than rewriting the I2 record.
- Privacy assertions now use structurally unique sentinels containing `/`, `~`
  or `%`, or inspect exact field absence. A recursive policy test scans every
  spec under `tests/**` and `test-human/**`; it follows simple constant-backed
  `not.toContain()` assertions, rejects regex private-sentinel exclusions, and
  rejects short whole-evidence substrings that use only the generated-ID
  alphabet. The live Codex test no longer searches every event for the short
  word `blue`; it requires exact absence of all content-bearing field names from
  observation data.

New product files are grouped under the `composition/delivery`, `queue`,
`diagnostics`, and `observation` domain folders. The largest composition
implementation file remains 218 lines. There is no global miscellaneous utility
module.

## Accounting defect found by the spike

The first overflow regression did not merely return an incorrect total: one
physical attempt reporting individually valid `MAX_SAFE_INTEGER` input and one
output token caused usage aggregation to throw after the model-call handle had
marked itself finalized. `call.report` then remained pending indefinitely.

The fix preserves all valid buckets, saturates totals, propagates the overflow
bit across aggregate rows, records `USAGE_COUNTER_OVERFLOW`, and prevents an
authoritative claim. Tests cover both one overflowing physical attempt and two
individually valid attempts whose sum overflows. A two-second installed-API guard
proves the report settles instead of hiding a future recurrence as a hanging test.

## Retained failed attempts and corrections

1. The first retry fixture produced no attempts because its fake transport had
   not declared provider-attempt accounting. It was corrected to exercise the
   actual provider-attempt context rather than fabricating report objects.
2. The overflow case timed out. Investigation identified the product finalization
   defect above; the production aggregator and handle were fixed and the original
   settling assertion retained.
3. Strict root typechecking rejected an optional staging-hook field that was
   explicitly assigned `undefined`. The field now declares its actual
   `callable | undefined` storage shape; strict compiler settings remain intact.
4. Initial small-queue tests exposed an invented constraint that batch limits
   must not exceed queue limits. That is false: an operator may intentionally
   configure a tiny retained queue while allowing a larger batch envelope, which
   also includes the separately serialized resource. The cross-limit constraint
   was removed; every limit remains independently validated as a positive safe
   integer, and exact wire feasibility is tested at item admission.
5. A post-pass scheduler audit found that a second flush could snapshot an item
   before the first flush released a failed best-effort delivery, then observe no
   active task and incorrectly infer full completion. The scheduler now tracks
   finished and incompletely delivered identities separately; a queued follow-up
   reports `required-complete` but never `complete` for that item. The two-flush
   race is retained in the focused suite.
6. Strict typechecking rejected diagnostic option keys explicitly assigned
   `undefined`. The port now omits absent keys instead of weakening
   `exactOptionalPropertyTypes`.
7. The first compaction accounting regression still observed two calls because
   the legacy package-level test loaded a stale built bridge. Rebuilding core and
   the bridge exposed the intended three calls: overflow, summarization and
   retry. The source-level runtime tests never depended on that stale artifact.
8. The new primary-failure oracle showed strict missing-usage policy replacing a
   terminal provider failure with `USAGE_REQUIRED`. Provider failure handling now
   runs first; coverage and `USAGE_REQUIRED` remain in the report without masking
   the primary code.
9. Refactoring compaction finalization initially preserved `MODEL_TIMEOUT` when
   the iterator also ignored teardown. The existing regression correctly
   required `MODEL_TEARDOWN_TIMEOUT`; teardown risk again takes precedence while
   the call is still finalized in accounting.
10. The original offline HTTP-provider privacy check searched the complete
    report for `bad`; those three letters occurred by chance inside a generated
    span ID. This is classified as a test-oracle false positive, not a product
    redaction failure. The failing observation remains recorded in the ledger;
    the malformed usage value is now the structural
    `PRIVATE_USAGE/VALUE~SENTINEL%` and a focused rerun is not accepted as a
    substitute for the broad gate.
11. The first run of the strengthened recursive policy failed on
    `FIXED_PRIVATE_KEY_3E91C8`, a constant-backed whole-report exclusion that the
    earlier literal-only scan missed. This is classified as a second test-oracle
    defect. The fixed-key value now has structural boundary characters and the
    assertion remains. After that correction, all 414 composition tests and all
    1,057 unit tests pass, and strict `tsc --noEmit` passes.

## Public mode contract discrepancy

The approved prose requires all three delivery modes, but the frozen exact
`AgentRuntimeOptions.observability` shape has no `mode` field. The internal port
therefore takes an explicit mode so behavior can be proven without guessing the
public grammar. Before `createAgentRuntime()` is exported, this must be resolved
as either an approved additive nested field or an explicit operational-only
scope. Inferring mode from exporter order or presence is not implemented.

## Still required

This increment does not expose the internal delivery helpers as a substitute
public runtime. Public option-mode reconciliation, diagnostic
health projection and new diagnostic ring still need to be connected to the canonical bus and
then to `createAgentRuntime()`. Agent/session/team bindings, full close order,
capability package closure, consumer migration, facade deletion and final live
human acceptance remain subsequent ledger work. Passing the installed core
matrix proves the overflow behavior of current public APIs; it does not prove the
unexported composition layer or a completed I3 runtime.
